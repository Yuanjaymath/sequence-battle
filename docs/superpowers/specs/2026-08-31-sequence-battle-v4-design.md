# 等差數列即時對戰 V4 設計規格

日期：2026-08-31
狀態：待使用者最終確認

## 目標

在不破壞既有 GitHub Pages + Supabase 即時對戰架構的前提下，完成下列七項改版：

1. 起始頁面連線文字由「Supabase 已就緒」改成「資料庫已連接」。
2. 移除「不用輸入房號」說明，改為隨機可愛小動物與隨機歡迎詞。
3. 房主建立等待房後，可以取消房間並回到已輸好名字的遊戲大廳。
4. 電腦、平板、手機橫向時，對戰畫面全部內容必須在單一螢幕內完整顯示，不需要捲動；手機直向時提示轉為橫向。
5. 勝利者顯示隆重祝賀與花瓣雨；落敗者顯示鼓勵詞。勝負畫面保留，玩家自行按「回到遊戲大廳」。
6. 題目項次全部使用 Unicode 下標字元 `₀₁₂₃₄₅₆₇₈₉`，例如 `a₂`、`a₁₀`。
7. 答對攻擊升級為「角色前衝放大 → 雷射 → 巨大刀斬 → 對手受擊」連段。

## 1. 起始頁面

### 1.1 資料庫連線文字

當 Supabase client 初始化成功時，右上角連線狀態顯示：

> 資料庫已連接

載入中、錯誤、離線等既有狀態文字保留其功能，只修改成功狀態文字。

### 1.2 隨機歡迎動物

移除目前起始頁面的「不用輸入房號」小標籤。

原位置改成一個歡迎區塊：

- 每次載入或回到遊戲初始頁時，從既有動物池隨機選一隻。
- 動物池沿用：小貓、小狗、小兔、小熊、狐狸、熊貓、企鵝、青蛙。
- 動物以較大的 emoji／角色圖示呈現。
- 旁邊或下方隨機顯示一則歡迎詞。

歡迎詞示例：

- 「準備開戰了嗎？」
- 「今天也來挑戰一下吧！」
- 「數列高手登場！」
- 「進大廳找個對手吧！」
- 「今天誰才是等差數列王者？」
- 「選好名字，準備出招！」

歡迎詞只影響視覺，不影響登入與房間流程。

## 2. 取消等待中的房間

### 2.1 前端流程

房主建立房間後，在「等待對手加入」畫面新增：

> 取消房間

按下後：

1. 按鈕進入 disabled 狀態，避免重複點擊。
2. 呼叫新的 Supabase RPC：`cancel_room(p_room_id, p_client_token)`。
3. 若取消成功：
   - 離開該房間 Realtime channel。
   - 保留目前玩家暱稱。
   - 回到遊戲大廳。
   - 重新訂閱 lobby realtime 並重新讀取等待房間。
4. 若取消失敗：顯示錯誤原因，重新啟用按鈕。

### 2.2 Supabase RPC

新增函數：

`public.cancel_room(p_room_id uuid, p_client_token uuid) returns jsonb`

安全條件：

- `p_room_id`、`p_client_token` 不可為空。
- 必須在 `players` 表中找到此 token，且 seat 必須是 1（房主）。
- 對 `rooms` 與對應 `game_state` 做鎖定／一致性檢查。
- 房間狀態必須仍為 `waiting`。
- 若已變成 `playing`，回傳／拋出 `ROOM_ALREADY_STARTED`，不可取消。

取消策略：採「軟取消」，不硬刪歷史資料。

- `rooms.status` → `finished`
- `game_state.status` → `finished`
- 更新 `updated_at`、`last_activity_at`、`finished_at`

效果：

- 該房間會立刻從等待大廳查詢結果消失。
- 相關歷史資料保留。
- 不新增新的資料表。

權限：

- `security definer`
- 固定 `search_path`
- 撤銷 public 預設 execute，再只 grant 給 `anon, authenticated`

## 3. 橫向單螢幕完整顯示

### 3.1 核心規格

電腦、平板、手機只要是橫向，對戰畫面必須：

- 不需要上下捲動。
- 不需要左右捲動。
- 同一螢幕完整看到：
  - 我方名字
  - 我方血量
  - VS
  - 對手血量
  - 對手名字
  - 雙方動物角色
  - 題型
  - 題目文字
  - A/B/C/D 四個選項
  - 即時回饋／勝負區

### 3.2 對戰配置

上方資訊列維持使用者已確認的排列：

`我方名字 | 我方血量 | VS | 對手血量 | 對手名字`

中段：

- 左：我方動物
- 右：對手動物

下段：

- 題型
- 題目
- 2x2 四選一按鈕

### 3.3 Responsive 策略

使用 CSS `clamp()`、`vh`／`dvh`、媒體查詢與高度級別壓縮：

- 一般桌機：角色與題目較大。
- 平板橫向：縮小上下留白與角色直徑。
- 矮螢幕手機橫向：進一步縮小角色、字級、按鈕高度、間距，但保留所有內容。
- `body` 在 battle mode 使用 `overflow: hidden`，避免誤捲動。
- 對戰 arena 高度依 `100dvh` 可用高度計算。

### 3.4 手機直向

手機直向時不強行塞入全部對戰內容；顯示全螢幕「請將手機橫向」提示。

使用者轉為橫向後提示自動消失並顯示完整遊戲。

## 4. 勝負演出

### 4.1 勝利玩家

當 `winner_seat === currentSeat`：

- 停止所有答題按鈕。
- 顯示大型勝利層。
- 隨機顯示隆重祝賀詞，例如：
  - 「🏆 王者誕生！等差數列霸主就是你！」
  - 「⚡ 完美制霸！這局完全被你掌控！」
  - 「👑 冠軍登場！你的數列火力無人能擋！」
- 播放花瓣雨約 4～6 秒。
- 加入角色歡呼、光暈／閃光效果。
- 保留「回到遊戲大廳」按鈕。
- 不自動跳頁。

### 4.2 落敗玩家

當 `winner_seat !== currentSeat`：

- 停止所有答題按鈕。
- 顯示鼓勵層。
- 隨機顯示鼓勵詞，例如：
  - 「差一點就反殺了！下一局再來！」
  - 「這局只是熱身，下局一定扳回來！」
  - 「已經很接近了，再挑戰一次！」
- 不播放勝利花瓣雨。
- 可以使用柔和光效／角色振作動畫。
- 保留「回到遊戲大廳」按鈕。
- 不自動跳頁。

### 4.3 花瓣雨實作

使用前端 DOM/CSS 動畫產生短生命週期花瓣元素：

- 不依賴外部圖片或套件。
- 動畫結束後清理節點。
- `prefers-reduced-motion: reduce` 時降低或關閉大量動畫。

## 5. Unicode 下標題目格式

新增純函數：

`toSubscript(value)`

數字對應：

- 0 → ₀
- 1 → ₁
- 2 → ₂
- 3 → ₃
- 4 → ₄
- 5 → ₅
- 6 → ₆
- 7 → ₇
- 8 → ₈
- 9 → ₉

範例：

- `toSubscript(2)` → `₂`
- `toSubscript(10)` → `₁₀`
- `toSubscript(18)` → `₁₈`

所有等差數列項次改為：

- `a₁`
- `a₂`
- `a₁₀`
- `a₁₈`

包含：

- 第一項描述
- 求第 n 項題型
- 已知兩項求公差
- 已知兩項求另一項

一般中文「第 10 項」仍可保留正常數字；只有數學符號 `a` 的索引使用 Unicode 下標。

## 6. 雷射 + 巨大刀斬攻擊連段

### 6.1 答對

每次 `last_event_type === 'hit'` 時，依攻擊方方向播放：

1. 攻擊方小動物向畫面中央前衝。
2. 同時放大約 1.25～1.35 倍。
3. 約 150～220ms 後射出既有雷射。
4. 雷射接近命中時出現巨大刀光／大刀圖形。
5. 大刀由攻擊方方向斜砍至對手方向。
6. 對手角色震動、短暫縮放或後退。
7. 畫面短促閃光。
8. 動畫結束後角色回原位。

左右兩方使用鏡像動畫。

### 6.2 大刀視覺

優先使用 CSS/DOM 產生，不依賴外部圖片：

- 大型刀刃輪廓／emoji 可作視覺核心。
- 搭配白藍刀光、速度線、旋轉與斜向位移。
- z-index 高於角色、低於勝負／斷線 overlay。
- 只在命中事件短暫存在。

### 6.3 答錯

答錯維持自己扣血與自損受擊，不播放雷射／大刀攻擊，避免誤解為攻擊成功。

## 9. 部署流程

1. 從最新 `main` 建立 implementation branch。
2. 依 TDD 先補純函數與行為測試，再修改 production code。
3. 新增 `supabase-phase3.sql`。
4. 前端與 SQL 完成後做完整驗證。
5. 建立 Pull Request。
6. PR 可合併後再合併至 `main`。
7. GitHub Pages 自動部署。
8. 使用兩台真實裝置做最後實機驗證。

注意：`supabase-phase3.sql` 必須由使用者在 Supabase SQL Editor 執行一次後，「取消房間」功能才會正式可用。
